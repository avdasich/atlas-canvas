## Стек и запуск

Frontend: React 19, TypeScript, Vite, Konva/react-konva, D3 Geo/TopoJSON. Настольная оболочка: Tauri 2 и Rust; SQLite через rusqlite, архивы ZIP и SHA-256. Системные файловые операции выполняются Rust-командами, не через произвольные пути из сцены.

```sh
npm ci
npm run tauri dev
```

Node.js 24 нужен в том числе для тестового загрузчика TypeScript через `node:module.registerHooks`. При проблемах с уведомлениями файловой системы можно использовать `ATLAS_POLLING=1 npm run dev`; обычный запуск Tauri выполняет beforeDevCommand самостоятельно. Браузерный preview — отдельное хранилище и ограниченный набор функций.

## Общий порядок глубины

Массив `scene.items` задаёт глубину объектов. `canvasRuns` разбивает последовательность на группы Konva между HTML-объектами; CSS z-index соответствует позиции в том же массиве. Поэтому таблицы/медиа не закреплены поверх всех фигур. `useHybridHitRouting` перенаправляет на верхний вектор события, которые браузер иначе отдал бы нижнему HTML-объекту. При изменениях этого слоя проверяйте не только картинку, но и выбор, drag, меню и ввод ячейки.

## Данные и инварианты

- Основной app identifier — `com.m1.tauri-app`: смена создаёт другое хранилище. Для тестов используйте отдельный identifier и переносите фикстуры через `.atlas`.
- country ID стабилен и не зависит от имени. 900–904 — дополнительные объекты источника, не новые ISO-коды.
- Текущая сцена — **schemaVersion 4**; frontend/native валидаторы читают 2/3/4. Для старых сцен дополняются отсутствующие поля. Не снижайте версию при сохранении: 0.2 должна отвергать новый формат, а не терять rich text/merges.
- SQLite `user_version=2` — отдельная версия схемы базы. Добавлена таблица preferences без пересоздания данных. Изменения DDL выполняются аддитивно; не путайте версию сцены с версией SQLite.
- Сцену сохраняйте через очередь `SceneWriter`; быстрые изменения и Undo не должны менять порядок записей. При ошибке последнее значение остаётся для повтора. Закрытие ждёт сцены и preferences.
- Операция сохранения атомарно сохраняет предыдущее состояние в revisions и заменяет текущую сцену. Несовместимый/битый JSON не подменяется пустым.
- Rich text — массив безопасных `RichRun`, plain content соответствует их тексту. HTML не является форматом хранения. Текст скрытых объединением ячеек сохраняется.
- Вложения адресуются внутренними ID; внешний исходник не является постоянной ссылкой. `safe_asset_path` допускает только управляемый путь внутри `assets/`.
- Не удаляйте медиа при удалении объекта: они могут использоваться Undo, версиями, библиотекой тем и другими странами. Сборщик мусора не реализован.
- Полный архив включает preferences и все их asset/font ссылки. При remap меняются структурные ID/`fontFamily`, а не произвольный текст заметок. До применения архива создаётся резервная или аварийная копия; отмена до commit откатывает новые файлы.
- Экспорт сначала завершает запись, затем получает сохранённую сцену. Так незавершённый текст/ячейка не экспортируются из устаревшего замыкания.

## Стиль кода

```sh
npm run format
npm run format:check
npm run docs:shortcuts
```

`format` сначала упорядочивает и очищает TS-импорты, затем применяет Prettier ко всем поддерживаемым рукописным файлам и rustfmt к Rust. Настройки: одинарные кавычки, ширина 100, завершающие запятые. Генерация/машинные ресурсы, lock-файл npm, исходные лицензии и бинарные шрифты исключены из Prettier, чтобы не переписывать чужие уведомления и объёмные данные. JSON lock-файлы обновляйте менеджером пакетов.

Используйте отдельные именованные функции для операций, явные типы границ компонентов и короткие комментарии для инвариантов. Не добавляйте новый инструмент сразу во все обработчики координатора: определите domain-преобразование, UI-свойства и действие отдельно. Новые сочетания добавляются в каталог и binding map; справочник Markdown генерируется из каталога.

## Проверки

```sh
npm test
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run format:check
git diff --check
```

Сейчас 40 frontend/domain-проверок и 13 Rust-проверок: геометрия/история, миграции, ошибки очередей, rich text, таблицы/объединения, привязка, слои, PDF, анимация, клавиши; целостность архивов, конфликты, remap ссылок, аварийные копии и откат/отмена. Список меняется вместе с тестами; точное количество смотрите в выводе запуска.

Ручная проверка обязательна для WebView/диалогов/кодеков: добавление и совместное выделение HTML/Konva, порядок и hit testing, редактирование текста/таблицы, сохранение/перезапуск двух стран, импорт/экспорт `.atlas`, PNG/PDF и отмена URL. Большие сцены проверяйте отдельно от обещания FPS: демонстрация 1000 объектов не является замером 60 fps на всех машинах.

Vite предупреждает о размере lazy-чанка детальной карты (~756 кБ без gzip). Он не входит в первоначальный чанк, но требует дальнейшей оценки на слабых системах; предупреждение не скрыто настройками сборки.

## Ресурсы и лицензии

`npm run notices` строит `public/licenses/notices.json` из production npm-зависимостей, Cargo metadata и локальных копий лицензий. Обновляйте после изменения зависимостей; перед публикацией проверяйте отчёт о компонентах, имеющих только SPDX-метаданные без полного текста. `public/licenses/upstream/index.json` хранит источники и commit SHA дополнительных текстов. Файлы лицензий не форматируются.

Шрифты и их хеши — в `public/fonts/SOURCES.md`. Геоданные входят в npm-пакет world-atlas; подробная карта импортируется лениво. Сеть и сторонние API для открытия локального атласа не требуются.
