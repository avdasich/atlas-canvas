# Разработка и выпуск

## Запуск из исходников

Нужны Node.js 24, Rust stable и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/). Для проверки демо нужен Python 3. В Cargo указан минимум Rust 1.88; отдельная проверка этого минимума в CI пока не настроена.

```sh
npm ci
npm run tauri dev
```

`npm run dev` открывает браузерную версию с отдельным хранилищем и ограниченными нативными функциями. При проблемах с отслеживанием файлов используйте `ATLAS_POLLING=1 npm run dev`. Локальная сборка приложения: `npm run tauri build`.

Для проверки с пустой базой используйте отдельный тестовый identifier:

```sh
npm run tauri build -- --debug --bundles app --config '{"identifier":"com.m1.atlas-canvas.my-check","productName":"Atlas Canvas My Check"}'
```

## Где что находится

| Каталог                       | Содержимое                                                    |
| ----------------------------- | ------------------------------------------------------------- |
| `src/components/`             | Карта, редактор, инструменты и панели свойств                 |
| `src/domain/`                 | Формат сцены, геометрия, таблицы, текст, обрезка и материалы  |
| `src/services/`, `src/state/` | Очереди сохранения, ввод, импорт, экспорт и Undo/Redo         |
| `src/i18n/`                   | RU/EN; переводы интерфейса не меняют содержимое холстов       |
| `src-tauri/src/`              | SQLite, файлы вложений, архивы, версии сцен и отмена операций |
| `tests/`, `scripts/`, `demo/` | Проверки, подготовка ресурсов и демонстрационный атлас        |

React 19 отвечает за интерфейс, Konva — за векторные объекты, Tauri 2 — за нативную оболочку. Порядок `scene.items` общий для Konva и HTML-объектов. При изменениях слоёв проверяйте изображение, выбор, перетаскивание и ввод в таблицах. Стекло и блестяшки экспортируются статическим снимком; размытие может отличаться от WebView.

## Данные и совместимость

- Сохраняйте основной identifier **`com.m1.tauri-app`**: он определяет папку данных. Не открывайте два экземпляра одной базы.
- Формат сцены — **5**, поддерживается чтение 2–5. SQLite **`user_version=2`**, манифест `.atlas` — **1**. Эти версии независимы; изменения требуют совместимых миграций.
- ID стран постоянны и не зависят от языка; 900–904 — дополнительные объекты источника карты. Пользовательский текст не переводится. `ui-language` хранится в SQLite и не переносится через архив.
- `SceneWriter` сохраняет сцены последовательно. Выход и экспорт ждут очереди сцен, настроек и текущего ввода. Ошибка чтения не должна подменять данные пустой сценой; запись сцены и её предыдущей версии выполняется транзакционно.
- Вложения лежат в управляемой папке `assets/`; доступ проверяет `safe_asset_path`. Не удаляйте оригиналы вместе с объектом: они могут понадобиться Undo, версиям, темам или другим странам. Один SQLite без вложений не является полной копией.
- Полный `.atlas` включает сцены, вложения и общие настройки. Перед восстановлением создаётся копия; отмена до commit откатывает новые файлы. Remap меняет структурные ссылки, а не текст заметок.
- Rich text хранится безопасными текстовыми фрагментами, а не произвольным HTML. Обрезка хранит нормализованную область и сохраняет оригинал; объединённые ячейки сохраняют скрытый текст. Черновики сносок входят в автосохранение, а раскрытие в режиме просмотра остаётся локальным.

## Автокопии

- После записи сцены запускается один фоновый worker. Он проверяет изменения через `MAX(scenes.updated_at)`; без изменений новая копия не создаётся. Изменения только общих настроек не запускают копирование.
- Проверки выполняются не чаще раза в 60 секунд. После ошибки архивации повтор разрешён через час после её завершения; успешный результат сбрасывает паузу, предупреждение очистки её не включает. Следующая попытка происходит при следующем сохранении после истечения интервала.
- Полный архив создаётся не чаще раза в час. Сначала записывается `.auto-<id>.<newid>.partial`, затем `.pending`, затем готовый `auto-*.atlas`. Время готовой копии отмечает начало архивации, чтобы последующие правки не считались уже включёнными.
- После успешной публикации остаются последние **5** автокопий. При первой новой копии после обновления старые автокопии сверх лимита удаляются безвозвратно. Ручные экспорты и копии перед восстановлением сохраняются.
- В начале worker удаляет только обычные `.auto-*.pending` и `.auto-*.partial`, оставшиеся после прерывания. Каталоги, символические ссылки, `before-import-*`, `recovery-*` и имена без `.auto-` не затрагиваются. Файлы текущего worker создаются после очистки.
- Очистка временных файлов выполняется best-effort: отказ удаления одного файла не мешает остальным и созданию архива. Ошибки создания идут через `atlas-backup-error`, очистки — через `atlas-backup-cleanup-warning`. Каждая пара «тип + исходный текст» показывается один раз за сессию, включая A → B → A.
- Статус **Сохранено** подтверждает запись холста, а не завершение фонового архива. Выход не ждёт автокопию; для завершённого снимка используйте ручной экспорт.

## Проверки перед PR

```sh
node scripts/check-version.mjs
npx tsc --noEmit
npm test
npm run format:check
npm run demo:check
cargo test --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings
git diff --check
```

`npm run format` форматирует код и упорядочивает импорты. `npm run docs:shortcuts` обновляет обе страницы горячих клавиш из общего каталога. `npm run notices` обновляет уведомления о зависимостях; запускайте его при изменении зависимостей и проверяйте полноту лицензий. Генерируемые данные и тексты лицензий не редактируются форматтером.

Вручную проверяйте установку, диалоги, кодеки, выбор перекрывающихся объектов, ввод, сохранение после перезапуска, импорт/экспорт и отмену длинных операций. Успешная сборка на одной ОС не заменяет запуск на остальных.

## Выпуск

`Desktop checks` проверяет PR и собирает четыре платформы: Intel Mac, Apple Silicon, Windows x64 и Linux x64. После слияния код проверяется в `main` повторно; изменения только Markdown и `docs/` эту повторную сборку не запускают. Общая матрица находится в `build-desktop.yml`, отдельный `Desktop release` готовит релиз по тегу. Артефакты Actions доступны 14 дней.

1. Выберите новый номер и обновите `package.json`, `package-lock.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` и `src-tauri/Cargo.lock`. Согласуйте CHANGELOG и `.github/RELEASE_NOTES.md`.
2. Выполните проверки выше, отправьте отдельный PR и дождитесь четырёх зелёных сборок. Скачайте артефакты и проверьте приложение на нужных системах.
3. После слияния отправьте тег текущей версии:

```sh
git switch main
git pull --ff-only origin main
node scripts/check-version.mjs
atlas_version=$(node -p "require('./package.json').version")
git tag "v$atlas_version"
RELEASE_TAG="v$atlas_version" node scripts/check-version.mjs --release
git push origin "v$atlas_version"
```

4. Дождитесь успешного `Desktop release`. В одном черновике должны быть пять установщиков — два DMG, EXE, DEB, AppImage — и `SHA256SUMS.txt`. Демо скачивается отдельно; GitHub добавляет исходники автоматически.
5. Проверьте описание, установку и сохранность записей, затем опубликуйте черновик. Черновики недоступны обычным пользователям. Уже опубликованные теги и файлы не заменяйте; используйте новый номер версии.

Для повтора сборки откройте **Actions → Desktop release → Run workflow** и укажите существующий тег. Скрипт проверяет совпадение тега, коммита и всех файлов версий. [Особенности установки и подписи пакетов](INSTALLATION.md) описаны в инструкции пользователя.

## Ресурсы

Демо — [demo/Atlas-Canvas-Iceland.atlas](../demo/Atlas-Canvas-Iceland.atlas); его сборка и проверка используют `demo/scenes.json`, `scripts/build-demo.py` и `scripts/check-demo.*`. Личные архивы исключены из Git. Источники материалов — в [demo/SOURCES.md](../demo/SOURCES.md), шрифтов — в [public/fonts/SOURCES.md](../public/fonts/SOURCES.md). Данные карты поставляются с `world-atlas`; локальный атлас не требует стороннего сервиса.

Лицензии хранятся в [public/licenses](../public/licenses), дополнительные источники — в `public/licenses/upstream/index.json`. Эти файлы входят в приложение и должны сохраняться в репозитории.
