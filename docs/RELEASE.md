# Установка, Git и выпуск

[README](../README.md) · [Руководство](USER_GUIDE.md) · [Проверки](DEVELOPMENT.md)

Эта страница для автора проекта: здесь команды Git и порядок публикации новой версии.
Если вы хотите просто установить приложение, откройте [инструкцию установки](INSTALLATION.md).

## Перед обновлением

Экспортируйте полный `.atlas` в текущей программе. У основной сборки сохраняйте identifier `com.m1.tauri-app`: тогда она откроет прежнюю базу и вложения. Тестовые QA-приложения с другими identifier имеют отдельные данные. Если заметки находятся в **Atlas Canvas QA 03**, сначала экспортируйте их именно оттуда, затем импортируйте в основную версию. Не переносите только файл SQLite без `assets/`.

0.3 сохраняет сцены формата 4. Программа 0.2 их отвергает. Чтобы вернуться к 0.2, нужен архив, экспортированный до обновления, или отдельная нетронутая копия её данных.

## Проверить и загрузить 0.3.0 на GitHub

Команды ниже предназначены для уже существующего репозитория. Сначала просмотрите diff: в commit попадут исходники, документация и поставляемые шрифты/уведомления, а не ваши личные холсты.

```sh
cd /Users/m1/atlas-canvas

git status --short
git diff --stat
npm ci
npm test
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run format:check
npm run notices
git diff --check

git add .
git diff --cached --stat
git commit -m "Release 0.3.0: snow shimmer, editor tools, shortcuts and documentation"
git push origin main
```

На `main` запустится **Platform builds**, который проверяет сборку macOS, Windows и Linux. Сначала дождитесь зелёного результата в [Actions](https://github.com/avdasich/atlas-canvas/actions). Эти результаты появятся только после вашего push; локальная проверка macOS не означает, что Windows/Linux уже прошли.

Затем создайте новый тег:

```sh
git tag v0.3.0
git push origin v0.3.0
```

Не используйте повторно `v0.2.0`. Если `v0.3.0` уже существует, не перезаписывайте его силой: выберите следующую версию и согласованно обновите `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` и `src-tauri/tauri.conf.json`.

## Когда появится Windows installer

Тег `v*` запускает workflow **Windows installer**. Rust и WebView2 могут заметно увеличить время первой сборки; фиксированного времени ожидания нет. Следите за текущим шагом и журналом, а не перезагружайте страницу релиза в ожидании файла.

Workflow проверяет соответствие тега версии приложения, запускает тесты и создаёт **draft prerelease** с NSIS-установщиком. Черновик виден владельцу/уполномоченным участникам; обычному посетителю ссылка может возвращать 404. Ссылка вида `releases/tag/untagged-…` часто относится к ещё не опубликованному черновику.

После успешной сборки:

1. Откройте [Releases](https://github.com/avdasich/atlas-canvas/releases), найдите draft для `v0.3.0` и нажмите редактирование.
2. Убедитесь, что тег именно `v0.3.0`, прикреплён `-setup.exe`, название и описание соответствуют версии.
3. Скачайте установщик и проверьте его на Windows.
4. Нажмите **Publish release**. Для предварительной версии оставьте отметку prerelease.
5. Откройте публичную страницу без входа и дайте пользователю ссылку на опубликованный релиз.

Если установка не прошла, сохраните сообщение и журнал конкретного шага Actions; новый тег не исправит ошибку кода сам по себе. `workflow_dispatch` позволяет повторить workflow вручную, но для однозначного выпуска удобнее использовать согласованный тег.

## Пакеты Platform builds

`.github/workflows/platform-checks.yml` собирает:

| ОС           | Результат                                            |
| ------------ | ---------------------------------------------------- |
| macOS        | `.app`, упакованный `ditto` в ZIP с сохранением прав |
| Windows      | NSIS `.exe`                                          |
| Ubuntu 24.04 | `.deb`                                               |

Эти файлы находятся в **Actions → запуск → Artifacts**, хранятся 14 дней и сами по себе не публикуются в Releases. При необходимости добавьте проверенные пакеты к релизу вручную. Windows tag workflow отдельно делает draft release.

## Локальная сборка

Сначала установите [официальные зависимости Tauri](https://v2.tauri.app/start/prerequisites/) для своей ОС, Node.js 24 и стабильный Rust.

```sh
npm ci
npm run notices
npm run tauri build
```

Результат находится в `src-tauri/target/release/bundle/`. Сборка выполняется на целевой платформе; обычный запуск macOS-команды не создаст готовый Windows installer. Команда `--debug --bundles app` создаёт тестовый macOS-пакет, а не release-оптимизированный дистрибутив.

Для безопасной ручной проверки можно создать отдельную сборку macOS:

```sh
npm run tauri build -- --debug --bundles app --config '{"identifier":"com.m1.atlas-canvas.my-check","productName":"Atlas Canvas My Check"}'
```

Такое приложение имеет пустую отдельную базу. Импортируйте демонстрационный `.atlas`, не меняйте identifier основной программы ради теста. Не запускайте два экземпляра одной базы во время проверки сохранения.
